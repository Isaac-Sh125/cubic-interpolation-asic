# Keysight VSA Signal-Quality Verification

This directory contains the MATLAB utilities used to convert project I/Q
results into MAT files for Keysight PathWave Vector Signal Analysis (VSA).

Keysight VSA was used at two chronological stages of the project:

    Pre-RTL fixed-point MATLAB model
                |
                v
        Keysight VSA validation
                |
                v
          RTL implementation
                |
                v
        Keysight VSA validation

The two stages verify system-level 64-QAM signal quality during different
points of the design process. They are not a direct bit-exact MATLAB-to-RTL
comparison.

## Stage 1 - Pre-RTL Fixed-Point Feasibility

Before RTL development, `verification/matlab/cubic_hardware.m` was used as a
hardware-oriented fixed-point feasibility model.

Its generated I/Q output was converted to a Keysight-compatible MAT
representation and evaluated in Keysight PathWave VSA using the
project-provided 64-QAM system reference/configuration.

This stage was used to verify that the fixed-point interpolation approach
provided acceptable signal quality before committing to the RTL implementation.

Representative captured MATLAB results are:

| L | MATLAB pre-FIR | MATLAB post-FIR |
|---:|---:|---:|
| 2 | 223.44 m%rms | 215.39 m%rms |
| 3 | 192.98 m%rms | 196.82 m%rms |
| 4 | 201.39 m%rms | 227.29 m%rms |
| 5 | 221.91 m%rms | 228.30 m%rms |

## Stage 2 - RTL Signal-Quality Validation

After RTL implementation, the captured post-FIR RTL I/Q outputs were converted
to the same Keysight-compatible representation and evaluated using the same
system-level VSA methodology.

Representative captured RTL results are:

| L | Output sample rate | RTL post-FIR EVM |
|---:|---:|---:|
| 2 | 120 MS/s | 217.53 m%rms |
| 3 | 180 MS/s | 177.20 m%rms |
| 4 | 240 MS/s | 176.42 m%rms |
| 5 | 300 MS/s | 267.23 m%rms |

The project signal-quality requirement is:

    EVM < 350 m%rms

All four preserved RTL operating modes satisfy this requirement.

## Reference Terminology

Two references appear in the verification flow and must not be confused.

### Keysight System Reference

The project-provided 64-QAM system reference/configuration was used by Keysight
VSA to evaluate the pre-RTL MATLAB fixed-point outputs and, later, the RTL
outputs.

This is the system-level reference associated with the EVM measurements.

### RTL-Derived Digital Regression Baseline

The file:

    out/output_golden.txt

belongs to a later digital-regression stage.

Despite its historical filename, it is the preserved validated L=5 RTL output
sequence. It is byte-identical to:

    results/verification/rtl_output_post_LPF/rtl_output_POST_LPF_L_5.txt

This RTL-derived baseline is used to verify that later RTL regression,
synthesized gate-level simulation and pad-level simulation preserve the
already validated RTL behavior.

It is not the external system reference used by Keysight during the pre-RTL
MATLAB feasibility verification.

## MATLAB Result Conversion

`float_iq_to_vsa.m` converts a two-column floating-point I/Q text file into a
Keysight-compatible MAT file.

Input format:

    I(float)   Q(float)

The generated MAT file contains:

- `Y` - complex I/Q sample vector
- `XDelta` - sample interval in seconds
- `InputZoom` - VSA amplitude scaling
- `XStart` - start time

Example for L=5:

    float_iq_to_vsa( ...
        'cubic_fixed16_strict_output_POST_LPF_L_5.txt', ...
        300e6, ...
        'matlab_post_filter_L5.mat');

## RTL Hexadecimal Result Conversion

`hex_iq_to_vsa.m` converts the two-column hexadecimal I/Q output generated by
the RTL testbench into the Keysight-compatible MAT representation.

Input format:

    I_hex   Q_hex

The final RTL FIR output is interpreted as:

- signed two's-complement representation
- word length: 16 bits
- fractional bits: 14

The output sampling frequency is:

    fs_out = L * 60 MS/s

Therefore:

| L | Output sample rate |
|---:|---:|
| 2 | 120 MS/s |
| 3 | 180 MS/s |
| 4 | 240 MS/s |
| 5 | 300 MS/s |

Example for L=5:

    hex_iq_to_vsa( ...
        'rtl_output_POST_LPF_L_5.txt', ...
        5, ...
        'rtl_L5.mat');

## MATLAB and RTL FIR Difference

The pre-RTL MATLAB feasibility model uses a 64-tap fixed-point FIR.

The final RTL implementation uses a different hardware-oriented 10-tap
symmetric FIR with an L-dependent coefficient bank.

The MATLAB post-FIR and RTL post-FIR sequences are therefore not expected to
be bit-exact equivalents.

Keysight VSA instead verifies the system-level signal quality independently at
the pre-RTL MATLAB stage and at the later RTL stage.

## EVM Interpretation

Keysight VSA reports EVM continuously during signal analysis. The displayed
value can vary slightly with the active measurement interval and analyzer
state.

For this reason, the repository preserves representative captured screenshots
rather than treating the displayed EVM value as an immutable constant.
