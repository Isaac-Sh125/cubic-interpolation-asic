======================================================================
 CUBIC INTERPOLATION DSP ASIC
 Keysight VSA 64-QAM Signal-Quality Verification
======================================================================

Purpose
-------
Keysight PathWave Vector Signal Analysis (VSA) was used to verify system-level
64-QAM signal quality at two chronological stages of the project.

Stage 1 - Pre-RTL fixed-point feasibility
-----------------------------------------
Before RTL development, `cubic_hardware.m` was used as a hardware-oriented
fixed-point MATLAB model.

The purpose of this model was to reproduce the expected finite-word-length
hardware behavior and verify the feasibility of the cubic interpolation
algorithm before committing to an RTL implementation.

The MATLAB output was evaluated in Keysight VSA using the project-provided
64-QAM system reference.

After the fixed-point MATLAB results demonstrated acceptable signal quality,
the design was implemented in synthesizable RTL.

Stage 2 - RTL signal-quality validation
---------------------------------------
After RTL implementation, the captured post-FIR RTL I/Q outputs were converted
to Keysight-compatible MAT files and evaluated using the same system-level
Keysight VSA methodology and reference.

The MATLAB and RTL results therefore represent two chronological validation
stages.

They are NOT presented as a direct sample-by-sample or bit-exact MATLAB-to-RTL
comparison.

----------------------------------------------------------------------
 Sampling Rates
----------------------------------------------------------------------

Original input sample rate:

    60 MS/s

Output sample rates:

    L=2 : 120 MS/s
    L=3 : 180 MS/s
    L=4 : 240 MS/s
    L=5 : 300 MS/s

----------------------------------------------------------------------
 Representative EVM Measurements
----------------------------------------------------------------------

Keysight VSA reports EVM continuously during analysis. The displayed value can
vary slightly with the active measurement interval and analyzer state.

The preserved screenshots are therefore treated as representative captured
measurements.

All values below are reported by Keysight VSA in m%rms.

       MATLAB        MATLAB          RTL
       pre-FIR       post-FIR        post-FIR
  L    [m%rms]       [m%rms]        [m%rms]
 ------------------------------------------------
  2      223.44         215.39         217.53
  3      192.98         196.82         177.20
  4      201.39         227.29         176.42
  5      221.91         228.30         267.23

Project signal-quality requirement:

    EVM < 350 m%rms

The pre-RTL MATLAB measurements established that the hardware-oriented
fixed-point implementation was feasible before RTL development.

The later RTL measurements demonstrate that all four implemented RTL operating
modes also satisfy the project EVM requirement.

Representative captured RTL EVM range:

    approximately 176 to 267 m%rms

----------------------------------------------------------------------
 MATLAB and RTL FIR Implementations
----------------------------------------------------------------------

The pre-RTL MATLAB feasibility model and the final RTL use different FIR
implementations:

    MATLAB fixed-point FIR : 64 taps
    RTL hardware FIR       : 10 taps, symmetric, L-dependent coefficients

Therefore, the MATLAB post-FIR and RTL post-FIR sample sequences are not
expected to be bit-exact equivalents.

Keysight VSA is used to verify the system-level signal quality independently at
each development stage.

----------------------------------------------------------------------
 Reference Terminology
----------------------------------------------------------------------

Two different references appear in the complete project verification flow.

1. Keysight system reference

   The project-provided 64-QAM reference used during system-level Keysight
   VSA verification.

   It was used first for the pre-RTL MATLAB feasibility model and later for the
   RTL signal-quality verification.

2. RTL-derived digital regression baseline

       out/output_golden.txt

   This file is the preserved validated L=5
   RTL output sequence.

   It is byte-identical to:

       results/verification/rtl_output_post_LPF/rtl_output_POST_LPF_L_5.txt

   and is used later to verify digital behavior preservation through RTL
   regression, synthesized gate-level simulation and pad-level simulation.

The Keysight system reference and `out/output_golden.txt` are therefore
different references serving different verification purposes.
